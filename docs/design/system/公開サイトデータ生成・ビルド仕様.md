# 公開サイトデータ生成・ビルド仕様

## 適用範囲と正本

公開サイト全体の生成呼出・成果物整合性・公開を扱うFN番号を持たない共通仕様。ランキングの規則は[FN-001](../functions/FN-001-ランキング集計仕様.md)、楽曲一覧生成は[FN-005](../functions/FN-005-楽曲一覧データ生成.md)、表示は[公開サイト共通設計](../screens/公開サイト共通設計.md)を正本とする。

`data/*.csv`を唯一の正本とし、公開JSONは再生成可能な派生物としてGit管理する。JSONを手編集せず、CSVへの逆反映もしない。FN-004による安全なcanonical反映と、このビルド・公開運用は別の責務である。

## 入出力と生成呼出

| 機能 | 入力（data/内） | 出力 | 状態 |
| --- | --- | --- | --- |
| FN-001 作家ランキング集計・ランキングJSON生成 | artists.csv、works.csv、songs.csv、song_artists.csv、creators.csv、song_creators.csv | site/data/rankings/<artist_id>.json | 実装済み。既定G00001 |
| FN-005 楽曲一覧データ生成 | 同上。releases/release_tracksは使用しない | site/data/songs/<artist_id>.json | 設計のみ。初期G00001 |

### 現在実装済み

[package.json](../../../package.json)の`npm run site:build`は`npm run rankings:generate`だけを実行する。入力はcanonical CSV、出力はランキングJSONであり、HTML/CSS/JavaScriptを変換する処理ではない。`site/`の静的ファイルと生成JSONが公開artifactになる。ローカル・CIで同じコマンドを使う。artist引数とランキング固有検証はFN-001を参照する。

### FN-005実装時の追加予定

`site:build`からFN-001とFN-005の独立した生成処理を呼ぶ。各機能が結合・導出・出力形式を保証し、共通ビルドは呼出と全体の成否を管理する。楽曲JSONのGit管理・再生成差分検査と画面契約検証をCIに追加し、いずれかの失敗で公開を止める。生成CLI名・詳細引数・呼出順序は実装時に確定する。今回コマンド・workflow・生成物は変更しない。

## 生成物の整合性

ローカルでcanonical更新後に再生成し、内容をレビューしてCSVと生成JSONをcommitする。CIも同じ入力・方式で再生成し、commit済みJSONとの一致を検査する。CIは生成結果を自動commit/pushしない。

現在のworkflowの差分検査は`git diff --exit-code -- site/data/rankings`であり、追跡済みランキングの差分を検出する。未追跡ファイルの存在まで保証する検査ではない。FN-005実装時は楽曲出力も対象にし、追加ファイルの追跡漏れを含む検査方法を具体化する。

## CI失敗条件・GitHub Pages公開条件（現行）

挙動の正本は[workflow](../../../.github/workflows/deploy-pages.yml)と[CI選択処理](../../../.github/scripts/ci-policy.cjs)、モード選択・運用手順は[CI運用ルール](../../../.github/CI.md)。ここでは公開ビルドとの接続を記す。

- build jobは空白検査、ランキング検証、site:build、ランキング再生成差分検査を両モードで実行する。各コマンドの非0終了で失敗する。
- フルではNode 20のnpm testと、別jobのNode 20/24でGate関連3テストを実行する。軽量ではこれらのテストstepを省略する。軽量でもbuild・ランキング検証・差分検査は省略しない。
- PRでは検証のみでartifact upload・Deployは行わない。main pushまたはmainのworkflow_dispatchでbuild成功後、site/のみをartifact化する。docs/やモックは含まれない。
- Deployはci_mode・build・両Gate job成功を前提とする。公開lock取得後、検証SHAが最新mainと一致する場合だけ公開stepを実行する。古いSHAは公開をスキップし、照会失敗はjob失敗になる。

楽曲JSON契約検査はまだCIに存在しない。PR #100で承認された追加予定と現行の検証を混同しない。

## JOB-001・ブラウザとの境界

JOB-001はFN-002の候補収集を定期起動する未実装ジョブであり、公開CIの別名ではない。候補の確認・FN-004反映を自動確定しない。公開CIはcanonicalから派生物を検証・生成・公開する既存運用である。

ブラウザは生成JSONを読み、画面側の形式確認・検索・並び替え・表示・読込エラー処理を行う。CSV結合・参照整合性・日付導出はFN-005、ランキング集計はFN-001が担当する。生成JSONと画面の契約整合性はCIで自動検証する設計とし、楽曲分は後続実装とする。
