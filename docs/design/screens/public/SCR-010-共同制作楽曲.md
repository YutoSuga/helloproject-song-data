# SCR-010 共同制作楽曲

[モック](../mockups/collaboration-detail.html)を参照。分析の詳細として、共通ナビに分析の現在位置を表示する。ホーム・組み合わせランキングの両方式・作家指定分析・作家詳細の曲数リンクから遷移する。

## URLと状態

`/analysis/detail/?artist_id=G00001&creator_id=C00001&partner_id=C00002`。異なる2人はID昇順に正規化し、逆順でも同じ結果を表示する。直接アクセス・リロードをサポートする。戻り先は[共通設計](../公開サイト共通設計.md)に従い、遷移元がなければ分析。IDの形式、不明の作家、公開対象外のアーティストはメッセージで区別する。作家は存在するが共担がない場合は0曲と空の案内を表示する。

## 表示

戻るリンク、見出し、アーティスト名、作家詳細へリンクする対象作家名（同一IDは1人分）、総曲数、担当区分別内訳、共同制作楽曲一覧、共通フッターの順。異なる2人は遷移元にかかわらず全担当区分を表示する。方向付きランキングの曲数とは異なる場合がある。「すべて」「作詞×作曲」の切り替えは置かない。同一IDは本人が同じSongで作詞と作曲を両担当したWorkに限り、既存の作詞×作曲ランキングの根拠と曲数を使用する。

## 担当構成の内訳

[分析の共通集計](SCR-009-分析.md)で得たWorkと根拠Song IDを使う。対象作家だけのクレジットから、同じSongに存在するすべての（役割、creator_id）を重複排除・整列し、1つの担当構成を作る。第三者のクレジットは内訳集計の対象外。担当方向や役割の増減は異なる構成として扱う。同一IDでは従来の作詞・作曲両担当のSongを取得し、そのSongにおける本人の全担当を使用する。

役割順は作詞、作曲、編曲、英語詞、ブラス編曲。同じ役割はcreator_id昇順。構成同士は同じ順序で各要素を比較し、途中まで一致した場合は短い構成を先に表示する。曲数は右揃え。構成ごとにWorkを重複排除し、根拠Song IDを保持する。音源間の担当構成の違いにより、内訳合計が総曲数を上回ることがある旨を表示する。

## 作品一覧

作品は初出日昇順、不明末尾・同日はWork ID昇順。Workを1行置き、根拠Song IDに含まれる音源だけをその配下に表示する。複数音源がある場合は「N音源」または「該当N音源／全M音源」と、登録済みの音源名・バージョン名を示す。Work全体に1音源のみの場合は音源見出しを省略する。

全作家の（役割、creator_id）の集合が同じ音源を同一グループとする。クレジットの登録順、表示名、名義は同一判定に用いない。グループと音源は初出日昇順（不明末尾・同日はSong ID順）で、先頭の音源の登録名義とクレジット順を表示する。同じ役割の複数人はまとめて表示する。複数グループはインデントと細い区切り線で示し、PC・SPともに長い表記は折り返す。全音源の個別クレジットはWork名から楽曲詳細で確認できる。

表示用の判定と整形はSCR-010でのみ実行する。公開JSON、canonical、順位・総曲数・根拠の抽出条件は従来の契約を使用する。
