# SCR-002 その他・サイト情報

URLは `/more/`。サイト紹介の下に、収録状況 → サイト更新履歴 → 収録方針 → ご意見・ご要望 → 免責事項の順で表示する。ホームから履歴へは `/more/#site-updates` で直接遷移する。

[HTMLモック](../mockups/more.html)の更新履歴はレビュー用の仮値。収録状況は公開予定の初期値を使用する。共通項目C-01〜07は[共通仕様](../公開サイト共通設計.md)を参照。アーティスト選択欄は設けず、収録状況の一覧でアーティスト名を表示する。

## 公開JSON・管理

配置は `site/data/about/`。静的ページはモジュール相対URLで読み込む。

- `updates.json` は手動管理する配列。要素は必須の `date` と空白のみでない `description` を持つ。確認済みの公開履歴のみを記載する。ホームと新画面で同じJSONを使用する。日付降順。同日内はJSONの掲載順を保つ。空配列を許容する。掲載日は Pages の成功時刻を日本時間に換算し、公開されたコミットの画面と照合する。同日内の初期履歴は公開時刻が新しい方を先に記載する。
  - 2026-11-22 19:20:50 JST。楽曲一覧・検索。デプロイ `7977312616`。 [PR #103 の公開](https://github.com/YutoSuga/helloproject-song-data/actions/runs/45005361387)
  - 2026-11-22 12:00:32 JST。ホーム・動画・その他と作家ランキングの移動。デプロイ `7973018446`。 [PR #101 の公開](https://github.com/YutoSuga/helloproject-song-data/actions/runs/44973870822)
  - 2026-10-10 23:40:13 JST。作詞・作曲の組み合わせ分析。デプロイ `6982338218`。 [PR #48 の公開](https://github.com/YutoSuga/helloproject-song-data/actions/runs/38060495726)
  - 2026-10-07 22:25:59 JST。サイトと作家ランキングの初公開。デプロイ `6911153758`。 [PR #43 の公開](https://github.com/YutoSuga/helloproject-song-data/actions/runs/37626115537)
- `coverage.json` は手動管理。`artists` 配列はホームと同じ8組をホームと同じ順に掲載する。空配列を許容する。
- 正本にIDがある行は `artist_id`、`status`、`covered_from`、`covered_through`、`reflected_at` が必須。IDは正本を参照し、重複不可。`listed` は楽曲一覧公開済み、`unlisted` はアーティスト単位の楽曲一覧が未公開。未公開の収録範囲は「未収録」、データ反映日は「—」で示し、日付は3項目すべて `null`。公開済みの場合、収録範囲の両端が確定していれば「YYYY/MM/DD ～ YYYY/MM/DD」、片方でも `null` なら「確認中」。データ反映日が `null` の場合も「確認中」。
- 正本に未登録の行は `name` だけを持ち、未収録として表示する。空白名、重複名、正本名との重複は不可。正本に登録した後はその位置でID付き行に切り替える。
- 公開済みの行には任意の `note` を設定できる。Juice=Juiceの注釈でNEXT YOU名義の対象音源を案内する。NEXT YOU は正本上の別IDで、「Next is you!」「大人の事情」は両名義が主名義。公開上の収録状況ではJuice=Juiceの欄に注釈として表示する。
- `covered_from` と `covered_through` は収録作業を完了した対象期間の開始日・終了日を手動で設定する。開始日はメジャーデビュー日に限らず、インディーズ時代の楽曲も対象に含む。登録音源の最古・最新日付から導出しない。両端が確定している場合は開始日が終了日以前であること。Juice=Juiceの初期値は2013-04-03〜2026-06-24。
- `reflected_at` は対象データを初回の作家ランキングで公開した日。Juice=Juiceの初期値は、Pagesデプロイ `6911153758` の成功日である2026-10-07 JST。各日付は実在する暦日 `YYYY-MM-DD` とし、未来日を許容しない。公開日の判定は日本時間。
- `artists.json` は正本から生成するID・表示名・登録音源数（`registered_audio_count`）の配列。件数は `songs.csv` と `song_artists.csv` を照合し、アーティストが `primary` の音源IDを一意に数える。収録範囲の日付による絞り込みは行わず、楽曲一覧公開済みの行に件数を表示する。`site:build` で手動JSONとIDの参照を検証し、`site:check-generated` で生成済みの表示名と登録音源数がコミットと一致するか確認する。
- `policy.json` は手動管理する方針文。`sections` の各要素は `title` と1件以上の `paragraphs` を持ち、`coverage_note` は範囲と反映日の説明。文言の根拠は [canonical データ仕様](../../data/データ仕様.md)と[楽曲一覧の公開JSON設計](SCR-003-公開JSON設計.md)。

## 状態・非機能仕様

更新履歴、収録状況、方針の読込状態は独立。読込中は「データを読み込んでいます。」、空の一覧は「表示できるデータがありません。」、HTTP・形式エラーは「データを表示できません。時間をおいて再読み込みしてください。」と表示する。状態変更は `role="status"` で通知する。データの誤りの連絡先は「ご意見・ご要望」の X リンクで案内する。リンクは読み込み結果にかかわらず利用できる。

共通ヘッダー・フッター・ナビ・フォーカス規則を適用。更新履歴は日付と本文を縦に配置し、収録状況は本文幅に応じて列数を変える。収録方針と連絡先のカード間隔は他のカードと共通。方針の末尾段落と連絡先の見出しから外側のマージンを取り、余白は各カードのパディングで確保する。免責事項はネイティブの `details` / `summary` で開閉する。
