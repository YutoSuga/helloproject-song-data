# SCR-002 その他・サイト情報

URLは `/more/`。サイト紹介の下に、収録状況 → サイト更新履歴 → 収録方針 → ご意見・ご要望 → 免責事項の順で表示する。ホームから履歴へは `/more/#site-updates` で直接遷移する。

[HTMLモック](../mockups/more.html)の収録状況と更新履歴はレビュー用の仮値。共通項目C-01〜07は[共通仕様](../公開サイト共通設計.md)を参照。アーティスト選択欄は設けず、収録状況の一覧でアーティスト名を表示する。

## 公開JSON・管理

配置は `site/data/about/`。静的ページはモジュール相対URLで読み込む。

- `updates.json` は手動管理する配列。要素は必須の `date` と空白のみでない `description` を持つ。確認済みの公開履歴のみを記載する。ホームと新画面で同じJSONを使用する。日付降順。同日内はJSONの掲載順を保つ。空配列を許容する。初期データは [PR #103](https://github.com/YutoSuga/helloproject-song-data/actions/runs/45005361387) と [PR #101](https://github.com/YutoSuga/helloproject-song-data/actions/runs/44973870822) の Pages 公開を確認した2件で、デプロイIDは順に `7977312616`、`7973018446`。ともに 2026-11-22 JST。
- `coverage.json` は手動管理。`artists` 配列はホームと同じ8組をホームと同じ順に掲載する。空配列を許容する。
- 正本にIDがある行は `artist_id`、`status`、`covered_through`、`reflected_at` が必須。IDは正本を参照し、重複不可。`listed` は楽曲一覧公開済み、`unlisted` はアーティスト単位の楽曲一覧が未公開。未公開の収録範囲は「未収録」、データ反映日は「—」で示し、日付は両方とも `null`。公開済みで未確定の日付は `null` とし「確認中」と表示する。日付が確定した場合は「デビュー ～ YYYY/MM/DD」。デビュー日の実日付は管理対象外。
- 正本に未登録の行は `name` だけを持ち、未収録として表示する。空白名、重複名、正本名との重複は不可。正本に登録した後はその位置でID付き行に切り替える。
- 公開済みの行には任意の `note` を設定できる。Juice=Juiceの注釈でNEXT YOU名義の対象音源を案内する。NEXT YOU は正本上の別IDで、「Next is you!」「大人の事情」は両名義が主名義。公開上の収録状況ではJuice=Juiceの欄に注釈として表示する。
- `covered_through` は収録作業を確認済みの終了日。登録済み音源の発売日と比較・同期しない。`reflected_at` は管理対象データがサイトに反映された確定日。いずれも実在する暦日 `YYYY-MM-DD` とし、更新日を含め未来日を許容しない。公開日の判定は日本時間。
- `artists.json` は正本 `artists.csv` から生成するIDと表示名の配列。`site:build` で手動JSONとIDの参照を検証し、`site:check-generated` で生成済みアーティスト名がコミットと一致するか確認する。
- `policy.json` は手動管理する方針文。`sections` の各要素は `title` と1件以上の `paragraphs` を持ち、`coverage_note` は範囲と反映日の説明。文言の根拠は [canonical データ仕様](../../data/データ仕様.md)と[楽曲一覧の公開JSON設計](SCR-003-公開JSON設計.md)。

## 状態・非機能仕様

更新履歴、収録状況、方針の読込状態は独立。読込中は「データを読み込んでいます。」、空の一覧は「表示できるデータがありません。」、HTTP・形式エラーは「データを表示できません。時間をおいて再読み込みしてください。」と表示する。状態変更は `role="status"` で通知する。既存の連絡先は読み込み結果にかかわらず利用できる。

共通ヘッダー・フッター・ナビ・フォーカス規則を適用。更新履歴は日付と本文を縦に配置し、収録状況は本文幅に応じて列数を変える。免責事項はネイティブの `details` / `summary` で開閉する。
