## 開き方・成果物

ディレクトリ全体を保持してindex.htmlをローカルPCのブラウザで直接開く構成。サーバー必須ではない。相対HTMLリンク、ローカルCSS、通常scriptだけを使用しCSV/JSON/APIを取得しない。全データはHTML（data属性・templateを含む）に置いた仮値。確定値・本番IDとして使用しない。

## レビュー手順

- PCサイドバーのサイト名・8組・ナビへスクロールで到達。SPホームは2列4行。他4ページはartist欄だけを横スクロール。Juice=Juiceが初期表示で見え、他7組はComing Soon・disabled。選択ボタンも遷移・データ変更を起こさない。
- 楽曲はwork単位。曲名/作家名検索（例「作品A 作家A」）、新旧/曲名順、空検索・0件を確認。曲名から音源詳細を開き、作品Aの2音源を確認。×/Escapeで終了し曲名に復帰。
- 作家は5カテゴリと組み合わせ分析。名前だけで根拠を開く。方向を選択し単一コンボボックスに作家名/IDを入力、上下/Enterまたは候補クリックで確定。不正入力・0候補・未選択・確定済み結果の保持、全組合せ時disabledを確認。根拠は曲名中心の仮データ（件数分の曲名を網羅するものではない）。
- R-01で正常／読込中／空／失敗、作家では組合せ未生成を確認。

## 今回の実測（2026-11-21）

Linux Chromium headless、同じファイルをlocalhost HTTPで配信して検証。

- 320/375/768/1024/1280px × 5ページの25組：ページ横はみ出しなし、ナビ1種類、8ボタン・非活性7・選択中1、番号ON/OFF。SPの選択中が領域内に収まり、ホーム4行、他4ページのscrollWidthと初期scrollLeft、先頭Coming Soonラベルが領域内であることを寸法検査。横スクロール操作も実行。
- 楽曲3作品→複数語検索1作品→検索0件→空検索復帰、発売日古い順・曲名順、作品Aの2音源、×/Escape・曲名へのフォーカス復帰。
- 作家5カテゴリ、名前→根拠、技術ID/role非表示、Escape・起点復帰、作詞者/作曲者の両方向でコンボ入力→矢印→Enter、不正入力で分析結果保持、Escapeで確定値へ復帰。
- 楽曲/作家の状態切替。JavaScriptエラーなし、外部要求なし。
- 5画面設計書No./項目IDとHTML（詳細template含む）を機械照合。設計書リンク・ページ間href・CSS/JSの存在、静的DOM idの一意性を検査。
