# ハロプロ作家研究所 公開サイト共通設計

PR #119マージ後を基準とする承認済みの再構成設計。URL・状態・画面の実装確認は[実装レビュー](../../history/reviews/creator-lab-implementation.md)を参照。

- 日本語名は「ハロプロ作家研究所」、英語名は「Hello! Project Creator Lab」。
- ホームのコピーは「ハロプロ楽曲を、作家から知る。」。説明は「楽曲と作家の関係をランキング・検索・分析から楽しむデータベース。」。
- ドメインは `hellosongdb.com`、リポジトリは `helloproject-song-data`。淡いピンク・ボルドー、非公式表記、スキップリンクを引き継ぐ。

## ナビゲーションとレイアウト

PCは現行のサイドナビ、SP（1023px以下）は固定ヘッダーと下部5項目ナビを使い、順序はホーム、ランキング、検索、分析、その他。ヘッダーのサイト名からホームへ移動する。全ナビで現在地を示し、詳細では選択欄の代わりに対象アーティスト名を表示する。その他にも選択欄は置かず、ナビを経由してアーティストを持ち回る。動画一覧はナビ・サイト内リンク・インデックス対象から外す。

SPでは固定領域とsafe-area分を本文に確保し、ナビを1行、カテゴリやタブを非折り返しとする。収まらないカテゴリ列はその領域だけ横スクロールでき、キーボード移動に追従する。検索・ランキング・楽曲・根拠一覧を横線で区切り、個々の行のカード化を避ける。ホームの概要は3指標を並べ、PCではランキング2枠を横並び、SPでは縦に並べる。横棒は同じ表内の最大値に対する作品数の割合を示し、順位・実数をテキストで併記する。詳細の見出し、戻るリンク、メタ情報、一覧の体裁を共通化する。

タブは矢印キー・Home・Endに対応し、確定時にパネルとURLを同期する。セレクトに明示ラベルを付け、固定UIでフォーカスが隠れないようにする。取得中・データなし・検索0件・URL不正・通信/形式エラーを区別する。ホームのデータ失敗時もナビと検索ショートカットを利用できる。

## URLとアーティスト

主要4画面の選択順は **公開済みのURL値 → 公開済みの保存値 → Juice=Juice（G00001）**。IDの許可リストは両方の派生JSONが揃う公開対象を明示し、収録状況や正本の登録の有無だけで可否を決めない。当面公開はG00001のみ。Coming Soonは現行候補名・順序を使う無効なoption。候補の公開IDが未採番の場合は画面ラベルだけを持つ。未知・未公開・空・重複した指定は無効。主要画面では解決値を `replaceState` でURLに書き、明示的に無効だった場合はフォールバックした旨を通知する。公開済みの解決値を名前空間付きの `localStorage` に保存する。保存不可でもURLと初期値で動作する。

アーティスト変更は履歴に追加し、対象アーティスト専用の作家ID・根拠表示・スクロールを初期化する。タブ・ランキングカテゴリ・検索語・楽曲ソートは維持する。取得中に切り替えた場合は古いリクエストを中止するか、その応答の描画を抑止する。詳細は `artist_id` と対象IDが必須で、暗黙のアーティスト切替や保存値の更新を行わない。不正形式・未公開・対象なし・取得失敗ごとに案内し、復帰先へのリンクを提供する。別の有効なartistを示す詳細からのリンクには、そのartistを付ける。

| 画面 | URL・状態 |
| --- | --- |
| ホーム | `/?artist_id=…&mode=all\|lyrics_composition`。省略はすべて |
| ランキング | `/ranking/?artist_id=…&category=all\|lyrics\|composition\|lyrics_composition\|arrangement`。既定all |
| 検索 | `/search/?artist_id=…&tab=songs\|creators&q=…&sort=new\|old\|title`。既定songs/new。sortは楽曲のみ |
| 分析 | `/analysis/?artist_id=…&tab=pairs\|creator&mode=all\|lyrics_composition&creator_id=…`。pairs・すべてが既定。作詞×作曲の `lyrics=1`, `composition=1`, `include_self=1` を保持 |
| 作家詳細 | `/creators/detail/?artist_id=…&creator_id=…&role=all\|lyrics\|composition\|arrangement\|other`。既定all |
| 楽曲詳細 | `/songs/detail/?artist_id=…&work_id=…`。必要に応じ `#song-<song_id>` で根拠音源へ |
| 共同制作楽曲 | `/analysis/detail/?artist_id=…&creator_id=…&partner_id=…`。両IDを昇順で正規化。直接アクセスの戻り先は分析 |
| その他 | `/more/`。遷移時は任意の `artist_id` を保持。既存アンカーを維持 |

パラメータは `URLSearchParams` で組み立てる。既知の列挙値のみ採用し、未指定・不正は既定値へ。無効な分析対象IDは選択を解除し案内する。両検索タブに入力がある場合はタブごとに当該履歴上のURLを復元する。初回に別タブへ進むときは空の検索条件から始める。検索語の入力は現在エントリを置換し、タブ・並び順・カテゴリ・確定した絞り込みは履歴へ追加する。

分析の `include_self` は一つだけ存在して値が `1` のときON。OFFはパラメータを省略し、不正値・重複はOFFとして正規化する。チェック変更は履歴へ追加し、再読込や戻る・進むではURLからチェックと順位を復元する。分析起点の詳細リンクの `from` にもこの値を許可する。作家指定分析タブへのURLには付けず、組み合わせタブの履歴へ戻ったときに復元する。アーティスト切替と、組み合わせタブ内で「すべて」と往復する場合はチェックを維持する。ホームから分析へ進むリンクは `include_self` を含めず、他の絞り込みも初期状態とする。

## 戻る操作

- ブラウザの戻る・進むではURLを再解釈し、復元されたDOMがあれば二重描画を避ける。必要時は履歴エントリごとのスクロール・起点要素を `history.state` と同一タブの `sessionStorage` に保存し、対象リストの描画後に復元する。再読み込み・新しいタブでもURLの条件は復元する。位置情報がなければ先頭へ。
- 詳細の戻るリンクには元画面の相対パス・条件を `from` で1段だけ渡す。元が同一タブの直前の履歴エントリと確認できれば履歴を戻り、それ以外はリンクとして遷移する。パスは画面一覧の同一オリジン許可リスト、パラメータは画面別許可リストで復元し、別オリジン・未知のパス・入れ子の `from` を拒否する。直接アクセスの戻り先は該当の検索タブ。旧形式の `view/category/q` も移行表どおり解釈する。
- 共同制作楽曲は独立画面。旧根拠パラメータ（`lyricist_id` と `composer_id`、または作家指定分析の `partner_id`）は、該当する行が有効なら新詳細へ置換し、無効なら取り除く。詳細から詳細へのリンクの `from` は遷移元の現在の状態だけを格納し、入れ子にはしない。履歴で戻る場合は元のURLとスクロール・起点フォーカスを復元する。

## 旧URLとメタデータ

| 旧URL | 新しい扱い |
| --- | --- |
| `/`、`/more/` | 同じパス。その他の `#data-policy`、`#artist-coverage`、`#site-updates`、`#disclaimer`、`#contact` を保持 |
| `/songs/` | `/search/?tab=songs`。既存の楽曲検索はURL状態を持たない。新URLでも有効なartist・q・sortは転送可 |
| `/creators/` | viewなし/searchは `/search/?tab=creators` にqを保持。rankingは `/ranking/` にcategoryを保持。pairsは `/analysis/?tab=pairs&mode=lyrics_composition`。旧一覧には選択・チェックが記録されていない |
| `/creators/detail/` | 同一パスと両IDを保持。fromがない旧リンクはview/category/qから戻り先を変換し、新規リンクと同様に扱う |
| `/videos/` | 動画UIの代わりに公開休止案内とホームへのリンクのみを置く。noindex。HTTP 200。通常のサイト内リンクを削除 |

GitHub Pagesの静的配信に合わせ、旧一覧ページは許可した条件だけで `location.replace` する静的互換ページとし、JS無効時は新画面への通常リンクを提供する。旧一覧にはnoindexと後継のcanonical。旧作家URLは転送先がクエリ依存なのでJSで解決し、素の旧URLでは作家検索を後継とする。末尾スラッシュ・旧 `index.html` でも到達できるよう検証する。

新HTMLに画面固有のtitle・description・canonical、静的な `og:site_name`、`og:title`、`og:description`、`og:url`、`og:type=website` を設定する。通常の検索・カテゴリ・戻り元パラメータはcanonicalから外す。公開画面は共通の `og:image=https://hellosongdb.com/assets/ogp.png` を参照し、画像の幅・高さ・代替テキストも設定する。クエリ型の詳細はnoindex、共通の静的OGPとブラウザ上の個別titleを使う。個別OGP・個別画像・そのための静的生成は将来対応。[共有画像設計](共有画像設計.md)

PC/SPの共通ヘッダー、フッター、その他の免責、READMEの公開サイト名、更新履歴の追記を合わせて更新する。
