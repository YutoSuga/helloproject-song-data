# PR #121 共同制作の追加改修・検証

基準は操作レビュー後の `5297cb36a298432c02e69b35e75fc6cd2e60baa6`。公開楽曲JSONから担当区分を問わない集計を追加し、既存作詞×作曲の公開JSONと生成処理を維持した。

## 画面と集計

| 起点 | 改修前 | 改修後 |
| --- | --- | --- |
| ホーム | 作詞×作曲TOP3のみ | すべて／作詞×作曲、競技順位の3位以内を全表示。集計方式を分析へ引継ぎ |
| 分析 | 作詞×作曲と作家指定、根拠モーダル | 既存2タブ内で全担当区分も集計。自己組み合わせは作詞×作曲のみ、モード往復で選択維持 |
| 作家詳細 | 担当順位、楽曲一覧 | 共同制作者TOP3と分析リンク。1024px以上で左右、1023px以下で縦並び |
| 共同制作楽曲 | モーダルと連番の音源リンク | 独立ページ。総数、担当別内訳、Workごとの成立パターン。Work・作家の詳細へ相互遷移 |

楽曲JSONのSongごとに作家IDと役割を集め、ID昇順の異なる作家ペアごとにWorkを1件とする。成立したSong IDはWorkと担当方向付きパターンの両方に保持する。内訳もWorkごとにパターンを1回ずつ数える。画面は同じ集計結果を利用する。同一IDの詳細は既存ランキングの自己作詞×作曲のWork・Song集合を使用する。

## 検証

- 通常テスト229件成功（既存225件と追加4件）。追加テストはWork／Songの重複・方向・同名別ID、同率TOP3、自己組み合わせ根拠、URL正規化を対象とする。
- Chromiumの公開サイト検証は320、390、768、1023、1024、1440pxで13状態（78ケース）。既存検索履歴と再試行を含み、共同制作の画面間集計、一方向ランキングと全担当区分の曲数差、モード・自己チェック復元、直接URL・連続遷移、長い名前と25内訳のfixture、アーティスト切り替えを検証する。
